1. SYSTEM OVERVIEW & ARCHITECTURE
================================================================================

1.1 High-Level Architecture & Principles
--------------------------------------------------------------------------------
The ETech Computers Front-End Application is engineered as a zero-dependency,
high-performance Single Page Application (SPA) built using standard HTML5,
Tailwind CSS (v3 CDN configuration), Vanilla JavaScript (ES Modules), jQuery (for AJAX
network communications), and CSS Custom Properties.

The architecture emphasizes modularity, separation of concerns, strict state
persistence, and zero client build overhead. Business logic is organized into
Controllers, Data Models, Components, and Dynamic Page Renderers, interconnected
via an ES Module Window Bridge (`script.js`).

Primary Architectural Pillars:
- Modular Controller Layer: Discrete controllers manage storefront and administrative features.
- Single Source of Truth CSS System: Global variables in `src/css/variables.css` enforce branding, colors, spacing, and typography.
- REST API Service Layer (`src/js/api/`): Clean network communication layer with centralized token management, normalized error surfacing, and sanitized logging.
- Database-Driven Architecture: Validation rules, entity integrity, and role-based permissions are enforced by the backend database.
- Backend Readiness: Formatted for direct drop-in integration with a Java Spring Boot REST API and MySQL database.

1.2 Single Page Application (SPA) Routing & Hash Navigation
--------------------------------------------------------------------------------
Routing is driven by URL hash fragments (`window.location.hash`) handled centrally
in `src/js/app/app.js`. When a hash change event fires, `handleRoute()` inspects
the URL, enforces route guards, toggles visibility on section elements
(`.page-section`), and executes page-specific lifecycle hooks.

Supported Routes & Viewports:
- `#home`: Main landing storefront, featuring hero 3D carousel, brand value props, top featured products, and featured partner brand carousel.
- `#shop`: Full product catalog with real-time multi-criteria filtering, search, pagination, and category chips.
- `#product?id=X` / `#product-details?id=X`: Dynamic hardware product specs, 5-image gallery, rating breakdown, and customer review submitting form.
- `#cart`: Interactive shopping cart drawer/table with real-time subtotal, tax calculation, and item quantity adjusters.
- `#checkout`: Multi-step checkout with distance-based shipping fee calculation, branch fulfillment selection, and order placement.
- `#login` / `#signup`: Authentication portal for login, registration, password visibility toggles, and role redirection.
- `#account`: Customer dashboard displaying profile metrics, editable user details, customer order controls, tracking, and cancellation.
- `#admin` / `#administrator`: Full-screen staff management console (hidden storefront header/footer/chatbot during active session).
- `#about`: Corporate profile page displaying company history, branch network, and executive mission.
- `#privacy` / `#terms` / `#warranty` / `#policies`: Interactive legal policy portal with print action and section accordions.
- `#deals`: Hot Deals promotional showcase with active deal countdown timers and discount matrices.

Route Protection & Security Guards:
1. Protected Customer Routes (`#checkout`, `#account`):
   - Checked via `isLoggedIn()`.
   - Unauthenticated access redirects automatically to `#login?redirect=<target_route>`.
2. Protected Admin Console Routes (`#admin`, `#administrator`):
   - Checked via `isLoggedIn()` and `user.isAdmin() || user.isStaff()`.
   - Unauthorized customers receive an "Access Denied" alert and are returned to `#home`.
3. Dynamic Shell Visibility:
   - When transitioning to `#admin`, the global header, store footer, and chatbot FAB are hidden (`classList.add('hidden')`) to provide a dedicated desktop workspace.

1.3 Module Binding & Global Window Bridge System (script.js)
--------------------------------------------------------------------------------
Because ES Modules maintain isolated module scope, inline HTML event attributes
(e.g., `onclick="addToCart(4)"` or `oninput="filterProductsTable()"`) cannot
access un-exported ES Module functions directly.

To bridge ES Modules with standard DOM event handlers without abandoning modular code:
- `script.js` imports every controller method, model accessor, and helper function.
- It executes `Object.assign(window, { ... })` upon load.
- This binds all necessary functions globally to the `window` object while keeping code modularly organized in separate `.js` files.

1.4 API Service Layer Architecture (src/js/api/)
--------------------------------------------------------------------------------
All HTTP communication with the backend is routed through dedicated API service modules:
1. `apiClient.js` (Base AJAX Client):
   - Configures base URL (`http://localhost:8080/api/v1`).
   - Handles JWT Bearer Token lifecycle (`getToken()`, `setToken()`, `removeToken()`).
   - Automatically handles HTTP 401 Unauthorized by purging session and redirecting to `#login`.
   - Formats and normalizes error messages from Spring Boot standard responses (`message` / `body`).
   - Logs performance duration (ms), HTTP method, endpoint, and status codes.
   - Automatically sanitizes sensitive fields (`password`, `currentPassword`, `newPassword`, `token`, `secret`, `cvv`) in console logs.
2. `userApi.js` (`AuthApi`, `UserApi`):
   - `AuthApi.login(username, password)` -> `POST /api/v1/auth/login`
   - `AuthApi.register(userData)` -> `POST /api/v1/auth/register`
   - `AuthApi.getCurrentUser()` -> `GET /api/v1/auth/me`
   - `UserApi.getUsers(params)` -> `GET /api/v1/users`
   - `UserApi.getUserById(id)` -> `GET /api/v1/users/{id}`
   - `UserApi.createUser(payload)` -> `POST /api/v1/users`
   - `UserApi.updateUser(id, payload)` -> `PUT /api/v1/users/{id}`
   - `UserApi.updateUserRole(id, rolePayload)` -> `PATCH /api/v1/users/{id}/role`
   - `UserApi.deleteUser(id)` -> `DELETE /api/v1/users/{id}`
   - `UserApi.updateSelfProfile(payload)` -> `PUT /api/v1/users/me/profile`
   - `UserApi.changePassword(payload)` -> `PUT /api/v1/users/me/password`
3. `brandsApi.js` (`BrandsApi`):
   - `BrandsApi.getAllBrands(params)` -> `GET /api/v1/brands`
   - `BrandsApi.getFeaturedBrands()` -> `GET /api/v1/brands/featured`
   - `BrandsApi.getBrandBySlugOrId(id)` -> `GET /api/v1/brands/{id}`
   - `BrandsApi.createBrand(payload)` -> `POST /api/v1/brands`
   - `BrandsApi.updateBrand(id, payload)` -> `PUT /api/v1/brands/{id}`
   - `BrandsApi.toggleFeatured(id, featured)` -> `PATCH /api/v1/brands/{id}/featured`
   - `BrandsApi.deleteBrand(id)` -> `DELETE /api/v1/brands/{id}`

1.5 Client-Side State Engine & Persistence Strategy
--------------------------------------------------------------------------------
- Active User Session: Stored under `etech_current_user` in `localStorage`, hydrated into `User` instances via `getCurrentUser()`.
- JWT Authentication Token: Stored under `etech_jwt_token` in `localStorage`.
- Shopping Cart: Stored under `etech_cart` in `localStorage` for immediate guest and customer responsiveness.
- Store Entity Caches: Catalog, orders, branches, deals, and policies synchronize with backend endpoints and cache locally for offline stability.

2.1 Aesthetic Archetype & Design Philosophy
--------------------------------------------------------------------------------
Archetype: Modern Light Precision Hardware Storefront
The visual language is tailored for high-performance PC hardware retail and
enterprise procurement. It replaces noisy neon gaming gradients with a clean,
structured layout consisting of pure white card surfaces, soft slate-50 canvas backgrounds,
crisp 1px slate-200 borders, royal engineering blue action triggers, and high-contrast typography.

Core Pillars:
- Pure White Canvas & Soft Slate Hierarchy: Pristine white (`#ffffff`) surfaces paired with soft slate (`#f8fafc`) page backgrounds.
- Structural Geometry: Hardware-inspired border radius (`4px` to `8px`) without soft bubble corners.
- Engineering Blue Focus: Royal blue (`#2563eb`) guides primary calls to action, badges, and focal elements.
- Technical Typography: Dual-font system separating body copy from technical SKUs and pricing data.

2.2 CSS Variables & Design Tokens (src/css/variables.css)
--------------------------------------------------------------------------------
All design tokens are defined under `:root` in `src/css/variables.css` as the single source of truth.

5.2 User Entity Model (`User` & `USER_ROLE` in `user_model.js`)
--------------------------------------------------------------------------------
```javascript
export const USER_ROLE = {
    CUSTOMER: 'CUSTOMER',
    STAFF: 'STAFF',
    ADMIN: 'ADMIN',
    SUPERADMIN: 'SUPERADMIN'
};

export class User {
    id;
    username;
    name;
    email;
    password;
    role;
    assignedBranch;
    createdAt;

    constructor(data = {}) {
        this.id = data.id ?? null;
        this.username = data.username ?? '';
        this.name = data.name ?? '';
        this.email = data.email ?? '';
        this.password = data.password ?? null;
        this.role = (data.role ?? 'CUSTOMER').toUpperCase();
        this.assignedBranch = data.assignedBranch ?? null;
        this.createdAt = data.createdAt ?? new Date().toLocaleDateString('en-US');
    }

    isSuperAdmin() { return this.role === USER_ROLE.SUPERADMIN; }
    isAdmin() { return this.role === USER_ROLE.ADMIN || this.role === USER_ROLE.SUPERADMIN; }
    isStaff() { return this.role === USER_ROLE.STAFF; }
    isCustomer() { return this.role === USER_ROLE.CUSTOMER; }
    getInitial() { return (this.name || this.username || 'U').charAt(0).toUpperCase(); }
}
```

================================================================================

6.1 Target Database Relational Schema Overview (DDL)
--------------------------------------------------------------------------------
- Primary Tables: `users`, `branches`, `categories`, `badges`, `brands`, `products`, `product_images`, `branch_inventory`, `deal_bundles`, `bundle_items`, `hot_deals`, `home_deal_banner`, `stock_transfers`, `product_reviews`, `product_behavior_history`, `orders`, `order_items`, `business_profile`, `legal_policies`.

6.2 Spring Boot REST API Endpoint Specifications
--------------------------------------------------------------------------------
- Auth: `POST /api/v1/auth/login`, `POST /api/v1/auth/register`, `GET /api/v1/auth/me`.
- Users: `GET /api/v1/users`, `POST /api/v1/users`, `PUT /api/v1/users/{id}`, `PATCH /api/v1/users/{id}/role`, `DELETE /api/v1/users/{id}`, `PUT /api/v1/users/me/profile`, `PUT /api/v1/users/me/password`.
- Products: `GET /api/v1/products`, `GET /api/v1/products/{id}`, `GET /api/v1/products/sku/{sku}`, `POST /api/v1/products`, `PUT /api/v1/products/{id}`, `DELETE /api/v1/products/{id}`.
- Brands: `GET /api/v1/brands`, `GET /api/v1/brands/featured`, `GET /api/v1/brands/{slugOrId}`, `POST /api/v1/brands`, `PUT /api/v1/brands/{id}`, `PATCH /api/v1/brands/{id}/featured`, `DELETE /api/v1/brands/{id}`.
- Orders: `GET /api/v1/orders`, `GET /api/v1/orders/my-orders`, `GET /api/v1/orders/{orderCode}`, `POST /api/v1/orders`, `PATCH /api/v1/orders/{id}/status`.
- Promotions: `GET /api/v1/promotions/bundles`, `GET /api/v1/promotions/hot-deals`, `GET /api/v1/promotions/home-banner`.
- Transfers: `GET /api/v1/transfers`, `POST /api/v1/transfers`, `PATCH /api/v1/transfers/{id}/status`, `GET /api/v1/transfers/metrics`.
- Categories & Badges: `GET /api/v1/categories`, `GET /api/v1/badges`, `POST /api/v1/badges/auto-assign`.
- Inventory: `GET /api/v1/inventory/health-report`, `PATCH /api/v1/inventory/{id}/settings`, `POST /api/v1/inventory/{id}/adjust`.
- Chatbot: `POST /api/v1/chat/message`.
- Profile & Policies: `GET /api/v1/business-profile`, `GET /api/v1/policies`, `GET /api/v1/policies/{slug}`.
- Financial Analytics: `GET /api/v1/analytics/overview`, `GET /api/v1/analytics/branch-revenue`, `GET /api/v1/analytics/top-products`.

6.3 Architectural Regulations: Database-Driven Frontend & Single Source of Truth
--------------------------------------------------------------------------------
1. Zero Hardcoded Roles & Enums:
   - All role definitions are centralized strictly in `USER_ROLE` within `src/js/models/user_model.js`.
   - Never duplicate role arrays or switch-cases across multiple controllers.
2. Zero Redundant Frontend Validations:
   - Database schema and Spring Security handle all validation rules, uniqueness, and constraints.
   - Frontend performs only basic empty checks and password match verification, surfacing backend error messages directly.
3. Zero Mock Storage Replication:
   - Database entities are fetched from backend endpoints; only session credentials and JWT tokens are stored client-side.
4. Sanitized Debug Logging:
   - API client calls log method, endpoint, duration, and status codes with automatic redaction of sensitive credentials.
